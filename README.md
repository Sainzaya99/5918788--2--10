# 과제 10: 정렬 알고리즘 성능 및 안정성 비교

선택 정렬, 버블 정렬(일반/조기 종료), 삽입 정렬을 C언어로 만들고 비교 횟수와 이동 횟수를 쟀습니다.

## 1. 실험 방법
- 데이터 10,000개를 만들었습니다. 각 데이터는 `key1`, `key2`, 원래 순서(`order`)로 되어 있고, 정렬은 `key1`만 보고 합니다.
- 비교 횟수: `key1`끼리 비교할 때마다 1회입니다.
- 이동 횟수: 데이터를 복사하거나 대입할 때마다 1회입니다. 두 데이터를 바꾸면 3회입니다.
- 같은 데이터를 복사해서 네 가지 정렬에 똑같이 사용했습니다.
- 난수는 직접 만든 생성기를 썼습니다. (컴퓨터마다 `rand()`가 달라서) 어디서 실행해도 결과가 같습니다.

## 2. 무작위 데이터 100번 실험
100번 모두 정렬이 올바르게 되었습니다.

| 정렬 | 총 비교 | 평균 비교 | 평균 이동 |
|---|---:|---:|---:|
| 선택 | 4,999,500,000 | 49,995,000 | 29,972 |
| 버블 | 4,999,500,000 | 49,995,000 | 75,003,881 |
| 버블 (조기 종료) | 4,998,597,413 | 49,985,974 | 75,003,881 |
| 삽입 | 2,501,128,421 | 25,011,284 | 25,021,291 |

- 선택 정렬은 항상 끝까지 확인해서 비교 횟수가 늘 같습니다. 대신 이동이 가장 적습니다.
- 버블 정렬은 옆 데이터끼리만 바꿔서 이동이 가장 많습니다.
- 삽입 정렬은 제자리를 찾으면 멈춰서 비교가 절반 정도입니다.
- 일반 버블과 조기 종료 버블은 비교가 평균 9,026회(약 0.02%)밖에 차이 나지 않습니다. 무작위 데이터는 거의 끝까지 교환이 일어나기 때문입니다.

## 3. 입력 상태별 비교
같은 원본 데이터로 세 가지를 만들었습니다.
- 정렬된 데이터: 미리 오름차순으로 정렬했습니다.
- 역순 데이터: 정렬된 데이터를 뒤집었습니다.
- 일부 정렬된 데이터: 정렬된 데이터에서 임의의 두 자리를 500번 서로 바꿨습니다. (전체의 5%)

결과 (비교 횟수 / 이동 횟수)

| 정렬 | 정렬됨 | 역순 | 일부 정렬 |
|---|---|---|---|
| 선택 | 49,995,000 / 0 | 49,995,000 / 15,075 | 49,995,000 / 1,509 |
| 버블 | 49,995,000 / 0 | 49,995,000 / 149,984,841 | 49,995,000 / 9,168,855 |
| 버블 (조기 종료) | **9,999** / 0 | 49,995,000 / 149,984,841 | 49,729,644 / 9,168,855 |
| 삽입 | **9,999** / 19,998 | 49,995,000 / 50,014,945 | **3,066,284** / 3,076,283 |

- **정렬된 데이터**: 조기 종료 버블과 삽입 정렬은 비교가 9,999회로 매우 적습니다. 조기 종료 버블은 첫 번째 순회에서 교환이 없으면 바로 끝나기 때문입니다. 선택 정렬과 일반 버블은 그래도 끝까지 비교합니다.
- **역순 데이터**: 모든 정렬이 가장 많이 비교합니다. 버블은 모든 쌍을 바꿔서 이동이 가장 많고, 조기 종료도 소용이 없습니다.
- **일부 정렬된 데이터**: 삽입 정렬이 가장 좋습니다. 흐트러진 데이터만 조금 옮기면 되기 때문입니다. 버블의 조기 종료는 비교를 약 0.5%만 줄였습니다.
- 정리하면 선택 정렬은 입력과 상관없이 비교가 같고, 삽입 정렬은 정렬에 가까울수록 빠릅니다. 버블 정렬은 이동이 많아 가장 느립니다.

## 4. 안정성 검증
**방법**: 각 데이터에 원래 순서(`order`)를 저장했습니다. 정렬 후 `key1`이 같은 두 데이터의 순서가 바뀌었으면 "위반" 1개로 셌습니다. 위반이 0개면 안정입니다.

**사용한 데이터**
- 과제 예시 4개: `(527,100)#0, (527,200)#1, (125,300)#2, (892,400)#3`
- `key1`이 0~49라서 중복이 많은 데이터 1,000개

**결과** (작은 예시에서 527끼리의 순서)

| 정렬 | 결과 | 1,000개 데이터 위반 수 | 판정 |
|---|---|---:|---|
| 선택 | #1 → #0 (바뀜) | 313 | 불안정 |
| 버블 | #0 → #1 (유지) | 0 | 안정 |
| 삽입 `>` | #0 → #1 (유지) | 0 | 안정 |
| 삽입 `>=` | #1 → #0 (바뀜) | 950 | 불안정 |

**원인**
- 선택 정렬: 최솟값을 멀리 있는 자리와 바꿉니다. 예시에서 `125`를 맨 앞으로 보내면서 `(527)#0`이 `#1`보다 뒤로 가 버렸습니다.
- 버블 정렬: 옆 데이터끼리 `>`일 때만 바꿉니다. 키가 같으면 바꾸지 않아서 순서가 유지됩니다.
- 삽입 정렬 `>`: 키가 같으면 멈춥니다. 새 데이터가 같은 키의 뒤에 들어가서 순서가 유지됩니다.
- 삽입 정렬 `>=`: 키가 같아도 계속 밀어서 새 데이터가 같은 키의 앞으로 들어갑니다. 그래서 순서가 뒤집힙니다. 또 더 많이 비교하고 밀어서 비교·이동이 약 4% 많았습니다.

## 5. AI 활용 내용
- Claude(AI)를 사용했습니다.
- 일부 정렬 데이터를 만드는 방법을 AI에게 물어 조사했습니다. 그중 "정렬된 데이터에서 임의로 일부를 교환하는 방법"을 골라 500번(5%) 교환하기로 했습니다.
- 작성한 코드를 AI에게 검토받아 비교 횟수를 두 번 세는 오류와 안정성 검사 오류를 고쳤습니다.
- AI의 답을 그대로 쓰지 않고 직접 실행해서, 모든 정렬이 올바른지와 비교 횟수가 이론값(49,995,000)과 맞는지 확인했습니다.
